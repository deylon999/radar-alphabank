# Радар — фронтенд

Новостная аналитика для руководителей крупного бизнеса: сервис учитывает контекст компании
и превращает поток новостей в инсайты о рисках и возможностях. Хакатон Альфа-Банка, трек
«Новостная аналитика для принятия бизнес-решений».

Главный сценарий: **описал компанию → увидел релевантные инсайты → открыл карточку → понял,
что делать**. Срочный риск стоит первым в ленте, до него один клик со старта.

| Экран            | Адрес            | Что на нём                                                                               |
| ---------------- | ---------------- | ---------------------------------------------------------------------------------------- |
| Лента            | `/`              | сводка за неделю, вкладки «Главное» и «Под наблюдением», фильтры, поиск, «Скрыть»        |
| Карточка инсайта | `/insights/:id`  | цепочка влияния, гипотеза отдельно от фактов, чек-лист «Что проверить», источники, отзыв |
| Профиль компании | `/company`       | описание, ссылки и документы → факты на подтверждение                                    |
| Уведомления      | `/notifications` | подключение Telegram, правила срочных уведомлений и сводки, превью сообщения             |

## Запуск

Нужен Node.js 24 (версия в `.nvmrc`) и npm.

```bash
nvm use
npm ci
cp .env.example .env
npm run dev
```

Приложение откроется на <http://127.0.0.1:5173> — сервер слушает именно этот адрес: на Windows
`localhost` может указывать на IPv6 и не открываться. По умолчанию данные отдают моки — бэкенд не
нужен. Режим ошибок для проверки экранов ошибок: добавьте к адресу `?mock=errors`.

## Скрипты

| Команда               | Что делает                                                                            |
| --------------------- | ------------------------------------------------------------------------------------- |
| `npm run dev`         | сервер разработки Vite                                                                |
| `npm run build`       | проверка типов и сборка в `dist/`                                                     |
| `npm run preview`     | раздаёт собранный `dist/`                                                             |
| `npm run typecheck`   | TypeScript в строгом режиме                                                           |
| `npm run lint`        | ESLint (strict + type-checked, react-hooks, jsx-a11y) и Prettier, ноль предупреждений |
| `npm run format`      | форматирует код Prettier                                                              |
| `npm run test`        | unit- и компонентные тесты Vitest + Testing Library                                   |
| `npm run e2e`         | e2e Playwright на 360, 768 и 1280 px, проверки axe                                    |
| `npm run check`       | `typecheck` + `lint` + `test` + `build` — то, что должно быть зелёным перед коммитом  |
| `npm run screenshots` | скриншоты всех экранов на 360, 768 и 1280 px в `docs/screenshots/pages-*`             |

Перед первым `npm run e2e` установите браузер: `npx playwright install chromium`.

## Переменные окружения

| Переменная       | По умолчанию            | Значение                                                      |
| ---------------- | ----------------------- | ------------------------------------------------------------- |
| `VITE_API_URL`   | `http://localhost:8000` | адрес бэкенда                                                 |
| `VITE_USE_MOCKS` | `true`                  | `true` — данные из `src/mocks` (MSW), `false` — настоящий API |

## Как переключиться на настоящий API

1. В `.env` поставьте `VITE_USE_MOCKS=false` и адрес бэкенда в `VITE_API_URL`.
2. Перезапустите `npm run dev` или пересоберите: при `false` MSW и фикстуры не попадают в сборку.
3. Бэкенд должен разрешать CORS для адреса фронтенда.

Контракт — в [`docs/api-contract.md`](docs/api-contract.md): эндпоинты, примеры, enum с
русскими подписями. Все ответы проверяются zod-схемами из `src/schemas`. Если формат
бэкенда разойдётся с контрактом, экран покажет понятную ошибку, а не сломается: правьте
схему и контракт в одном месте, не ослабляя проверку.

## Структура

```
src/
  app/        провайдеры, роутер, шапка и навигация, выбор компании, error boundary, стили
  pages/      тонкие страницы: только собирают фичи
  features/   feed, insight, company-profile, notifications
  schemas/    zod-схемы и выведенные из них типы
  api/        http-клиент, эндпоинты, хуки TanStack Query, ключи запросов
  mocks/      MSW-обработчики и детерминированные фикстуры трёх вымышленных компаний
  shared/     ui-обёртки, форматтеры дат и чисел, русская типографика, подписи enum
  test/       общие помощники тестов
e2e/          сценарии Playwright, axe, скриншоты (*.shot.ts)
docs/         контракт API и скриншоты
```

## Правила продукта, которые проверяют тесты

- Возможное последствие всегда подписано «Гипотеза» и визуально отличается от фактов.
- В интерфейсе нет процентов вероятности и «уверенности модели».
- У каждого инсайта видны источники: издатель, дата, ссылка.
- Есть и риски, и возможности — в ленте, фильтрах и моках.
- Обратная связь добровольная и ничего не блокирует.

# Радар — фронтенд

Сервис для руководителей крупного бизнеса внутри интернет-банка Альфа-Бизнес: берёт поток
новостей, аналитику Альфа-Банка и данные о компании клиента и показывает, какие события
касаются именно этой компании, какие риски и возможности они создают и как их оценивает
банк. Хакатон Альфа-Банка, трек «Новостная аналитика для принятия бизнес-решений».

Главный сценарий: **главная Альфа-Бизнеса → виджет «Радар» → срочный инсайт → почему касается,
как оценивает банк, что сделать → уточняющий вопрос**.

| Экран                 | Адрес                 | Что на нём                                                                                         |
| --------------------- | --------------------- | -------------------------------------------------------------------------------------------------- |
| Вход и регистрация    | `/login`, `/register` | вход по email и паролю, второй фактор, демо-аккаунты владельцев компаний                           |
| Главная Альфа-Бизнеса | `/business`           | точка входа: виджет Радара со сводкой и самым срочным инсайтом, счёт, продукты банка               |
| Лента                 | `/`                   | сводка за неделю, вкладки «Главное» и «Под наблюдением», фильтры, поиск, учтённые признаки         |
| Обзор                 | `/overview`           | выводы по темам с балансом рисков и возможностей и по материалам банка                             |
| Качество выводов      | `/quality`            | для команды и жюри: полезность, открытия, скрытия, полнота, реакция, отзывы и вопросы              |
| Карточка инсайта      | `/insights/:id`       | что произошло, почему касается, позиция банка, гипотеза, основания, вопрос, шаги агента, источники |
| Профиль компании      | `/company`            | данные банка о клиенте, роль пользователя, описание и документы → факты на подтверждение           |
| Уведомления           | `/notifications`      | подключение Telegram, правила срочных уведомлений и сводки, превью сообщения                       |

## Архитектура

```
Браузер ──► фронтенд (React, этот репозиторий) ──► API бэкенда ──► агент, данные, аналитика банка
              │
              └── в режиме моков запросы перехватывает MSW (src/mocks) — бэкенд не нужен
```

- Фронтенд не вызывает модели и не хранит данные клиентов: всё приходит из API бэкенда
  по спецификации [`api/`](../api/); что важно фронтенду — в
  [`docs/api-contract.md`](docs/api-contract.md).
- Каждый ответ API проверяется zod-схемами (`src/schemas`). Если формат разойдётся с
  договором, экран покажет понятную ошибку, а не сломается.
- Интерфейс разделяет источники выводов: факты из новостей, «Позиция банка» (выжимка из
  аналитики Альфа-Банка с материалом и датой) и «Вывод AI» (интерпретация модели).
  Пересмотренная оценка банка и устаревший материал показываются явно.
- Компоненты: React 19, TypeScript, Vite, дизайн-система Альфа-Банка `@alfalab/core-components`,
  TanStack Query, React Router. Полный список с лицензиями — в
  [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md).

## Требования к окружению

- Node.js 24 (версия в `.nvmrc`) и npm — для запуска без Docker.
- Или Docker — тогда Node не нужен.
- Версии зависимостей зафиксированы в `package-lock.json` (`save-exact`).

## Запуск

### Локально

Все команды — из каталога `frontend/`.

```bash
cd frontend
nvm use
npm ci
cp .env.example .env
npm run dev
```

Приложение откроется на <http://127.0.0.1:5173/business> — сервер слушает именно этот адрес:
на Windows `localhost` может указывать на IPv6 и не открываться. По умолчанию данные отдают
моки — бэкенд не нужен. Режим ошибок для проверки экранов ошибок: добавьте к адресу `?mock=errors`.

### Docker

```bash
cd frontend
docker build -t radar-web .
docker run --rm -p 8080:80 radar-web
```

Сайт — на <http://localhost:8080/business>. По умолчанию образ собирается с моками. С настоящим
бэкендом:

```bash
docker build -t radar-web --build-arg VITE_USE_MOCKS=false --build-arg VITE_API_URL=https://api.example.com .
```

Образ — статический nginx (`nginx.conf`): маршруты сайта отдают `index.html`, файлы сборки
кешируются, `index.html` и Service Worker моков — нет.

### Демо в интернете

Сайт развёрнут на Vercel (`vercel.json`, в настройках проекта Root Directory — `frontend`): начните с адреса `/business`.

## Сценарий проверки

0. Войдите: на `/login` нажмите «Войти как u9250@demo.radar». Демо-аккаунты владельцев
   компаний из датасета (пароль у всех `radar-demo-2026!`):

   | Email               | Компания                                 |
   | ------------------- | ---------------------------------------- |
   | `u9250@demo.radar`  | Клиент U_9250 — стройка, кредиты, импорт |
   | `u34911@demo.radar` | Клиент U_34911 — экспорт зерна           |
   | `u26030@demo.radar` | Клиент U_26030 — опт топлива             |
   | `u1465@demo.radar`  | Клиент U_1465 — импорт напитков          |

   `cfo@demo.radar` — тот же пароль и вход с 2FA, код `123456`; это участник U_9250 без прав
   владельца и без доступа к метрикам качества. `newcomer@demo.radar` — пользователь без
   компании: его заявка в U_9250 ждёт решения, а в профиле U_9250 владелец видит её в разделе
   «Сотрудники» и может принять.

   Каждый пользователь видит только свою компанию — переключателя клиентов нет: другая компания —
   другой демо-аккаунт.

1. Откройте `/business` — главная Альфа-Бизнеса клиента U_9250 (стройка, Иркутская область,
   кредиты, лизинг, импорт из Китая). Виджет «Радар» показывает сводку и срочный риск.
2. Нажмите на срочный риск «ЦБ сохранил ставку 14%…». В карточке:
   - «Почему это касается вас» — цепочка влияния и признаки компании, на которых построен
     вывод (метка «Вывод AI»);
   - «Как оценивает Альфа-Банк» — позиция банка с материалом и датой (метка «Позиция банка»)
     и блок «Банк пересмотрел оценку»: было 13,5% (31 июля) → стало 14% (11 сентября);
   - «Возможное последствие» — подписано «Гипотеза»;
   - «Задать вопрос» — нажмите «Что будет при ставке 12%?»: пока агент работает, видны его
     шаги и кнопка «Отменить»; ответ — со ссылками на аналитику банка, данные клиента и новость
     и с шагами «Как агент искал ответ». В моках шаги описывают, как мок собирает ответ;
     настоящие шаги присылает агент бэкенда (поток, см. договор API);
   - «Как получен вывод» — шаги агента, включая самопроверку противоречия материалов;
   - справа — «Что проверить» и предложение банка.
3. Вернитесь в «Ленту»: у карточек видно, какие признаки компании учтены и есть ли оценка банка.
   Откройте «Металлопрокат дорожает…» во вкладке «Под наблюдением» — материал банка 2021 года
   помечен как устаревший.
4. Переключите клиента в шапке: поиск по ID, отрасли, коду ОКВЭД или региону (U_34911 —
   экспорт зерна, U_26030 — опт топлива, U_1465 — импорт напитков). Лента и выводы меняются
   под компанию.
5. «Обзор» — те же выводы в другом разрезе: по темам (где сосредоточены риски) и по материалам
   банка (на какой обзор опирается каждая оценка, устаревший — в конце с пометкой).
6. «Качество выводов» (`/quality`, ссылка внизу «Обзора») — метрики для команды: доля полезных
   оценок, открытия и скрытия, полнота выводов, время реакции, последние отзывы и вопросы
   агенту. Оцените вывод или задайте вопрос — число на экране сразу изменится.
7. «Профиль компании» — данные банка о клиенте (ОКВЭД, выручка, продукты, ВЭД, контрагенты)
   и выбор роли пользователя.
8. Переключатель темы в шапке — тёмная тема Альфа-Банка.

## Скрипты

| Команда               | Что делает                                                                            |
| --------------------- | ------------------------------------------------------------------------------------- |
| `npm run dev`         | сервер разработки Vite                                                                |
| `npm run build`       | проверка типов и сборка в `dist/`                                                     |
| `npm run preview`     | раздаёт собранный `dist/`                                                             |
| `npm run typecheck`   | TypeScript в строгом режиме                                                           |
| `npm run lint`        | ESLint (strict + type-checked, react-hooks, jsx-a11y) и Prettier, ноль предупреждений |
| `npm run format`      | форматирует код Prettier                                                              |
| `npm run test`        | unit- и компонентные тесты Vitest + Testing Library                                   |
| `npm run e2e`         | e2e Playwright на 360, 768 и 1280 px, проверки axe                                    |
| `npm run check`       | `typecheck` + `lint` + `test` + `build` — то, что должно быть зелёным перед коммитом  |
| `npm run screenshots` | скриншоты всех экранов на 360, 768 и 1280 px в `docs/screenshots/pages-*`             |

Перед первым `npm run e2e` установите браузер: `npx playwright install chromium`.

## Переменные окружения

| Переменная       | По умолчанию            | Значение                                                      |
| ---------------- | ----------------------- | ------------------------------------------------------------- |
| `VITE_API_URL`   | `http://localhost:8000` | адрес бэкенда                                                 |
| `VITE_USE_MOCKS` | `true`                  | `true` — данные из `src/mocks` (MSW), `false` — настоящий API |

## Как переключиться на настоящий API

1. В `.env` поставьте `VITE_USE_MOCKS=false` и адрес бэкенда в `VITE_API_URL`.
2. Перезапустите `npm run dev` или пересоберите: при `false` MSW и фикстуры не попадают в сборку.
3. Сайт и API должны быть на одном сайте: cookie сессии `SameSite=Lax`. На Vercel `/api`
   будет проксироваться на бэкенд — настроим, когда появится его адрес.

Договор — спецификация [`api/`](../api/) (эндпоинты, поля, enum, ошибки), что важно
фронтенду — в [`docs/api-contract.md`](docs/api-contract.md). Все ответы проверяются
zod-схемами из `src/schemas`. Если формат бэкенда разойдётся со спецификацией, экран покажет
понятную ошибку, а не сломается: правьте спецификацию и схемы в одном PR, не ослабляя проверку.

## Структура

```
src/
  app/        провайдеры, роутер, шапка и навигация, выбор компании, error boundary, стили
  pages/      тонкие страницы: только собирают фичи
  features/   feed, overview, quality, insight, company-profile, notifications, business
  schemas/    zod-схемы и выведенные из них типы
  api/        http-клиент, эндпоинты, хуки TanStack Query, ключи запросов
  mocks/      MSW-обработчики и фикстуры: четыре клиента из датасета кейса
  shared/     ui-обёртки, форматтеры дат и чисел, русская типографика, подписи enum
  test/       общие помощники тестов
e2e/          сценарии Playwright, axe, скриншоты (*.shot.ts)
docs/         контракт API и скриншоты
```

## Правила продукта, которые проверяют тесты

- Позиция банка и выводы AI подписаны и визуально различаются; устаревший материал банка
  помечен, пересмотренная оценка показана рядом с новой.
- Возможное последствие всегда подписано «Гипотеза» и визуально отличается от фактов.
- В интерфейсе нет процентов вероятности и «уверенности модели».
- У каждого инсайта видны источники: издатель, дата, ссылка.
- Есть и риски, и возможности — в ленте, фильтрах и моках.
- Обратная связь добровольная и ничего не блокирует.

# Договор API: что важно фронтенду

Сам договор — эндпоинты, поля, enum, коды ошибок — живёт в спецификации
[`api/`](../../api/) на TypeSpec. Она единственный источник правды. Собрать OpenAPI:

```bash
cd api && npm ci && sh compile.sh   # → api/tsp-output/schema/openapi.yaml
```

Готовый `openapi.yaml` есть и в артефактах проверки `api / spec` каждого PR, который меняет `api/`.

Фронтенд проверяет каждый ответ zod-схемами из `src/schemas/`: всё, что не совпадает,
показывается как ошибка. Если меняется формат — сначала спецификация, потом в том же PR схемы
и моки фронта (`src/mocks/`).

Ниже — то, чего в спецификации нет: как интерфейс показывает поля и что из этого следует для
бэкенда и агента.

## Кто что пишет в инсайте

Кейс требует, чтобы пользователь видел, какие выводы — позиция банка, а какие сделала модель.
Интерфейс подписывает поля так:

| Поля                                                  | Что это                               | Подпись в интерфейсе    |
| ----------------------------------------------------- | ------------------------------------- | ----------------------- |
| `event`, `basis`, `sources`                           | факты из новостей и данных клиента    | без метки, с источником |
| `bankView`                                            | выжимка из аналитики Альфа-Банка      | «Позиция банка»         |
| `whyItMatters`, `impactPath`, `consequence`, `checks` | интерпретация модели                  | «Вывод AI»              |
| `signals`                                             | признаки клиента, повлиявшие на вывод | «Признаки компании»     |
| `trace`                                               | шаги агента                           | «Как получен вывод»     |
| `offer`                                               | продукт банка, уместный в контексте   | «Предложение банка»     |

Позицию банка модель не придумывает: в `bankView.summary` — только то, что есть в материале
`bankView.material`. Если по теме материала нет, поле не передаётся.

## Что видит пользователь

- `consequence` — всегда гипотеза, интерфейс подписывает её «Гипотеза». **Не присылайте
  вероятности, «уверенность модели» и проценты достоверности** — по правилам продукта
  интерфейс их не показывает.
- `basis` — только установленные факты; догадки — в `consequence` и `unknowns`.
- `signals` — только признаки клиента, которые действительно повлияли на вывод.
- `trace` и шаги в потоке ответа агента — то, что видит пользователь: без внутренних промптов
  и служебных данных.
- `title` — до ~90 символов: в ленте он обрезается после двух строк.
- `bankView` — только при наличии материала банка по теме; устаревший материал помечается
  `outdated`, и интерфейс предупреждает, что на него нельзя опираться.
- Тексты ошибок `detail` и `title` интерфейс показывает как есть: понятный русский текст, без
  кодов и стектрейсов. Случаи фронтенд различает по `type`.
- Подписи enum на русском — в `src/shared/labels.ts`, интерфейс берёт их только оттуда.

## Как фронтенд ходит в API

- Базовый адрес — `VITE_API_URL`, пути начинаются с `/api`.
- Cookie сессии — `SameSite=Lax`, поэтому сайт и API должны быть на одном сайте: Vercel
  будет проксировать `/api` на бэкенд (настроим, когда появится его адрес).
- Таймаут — 15 с; загрузка документов и вопрос агенту — 60 с.
- Вопрос агенту — поток `text/event-stream`: шаги показываются по мере прихода, свои шаги
  фронтенд не придумывает.

## Моки

- Включаются `VITE_USE_MOCKS=true`. MSW перехватывает запросы к `VITE_API_URL` в браузере, поэтому переход на настоящий бэкенд — это `VITE_USE_MOCKS=false` и правильный `VITE_API_URL`.
- Данные: четыре клиента из датасета кейса (U_9250, U_34911, U_26030, U_1465) и 21 инсайт.
  Позиция банка — короткие выжимки из материалов кейса с названием, датой и страницей. Новости
  вымышлены, помечены «(тестовые данные)» и ведут на `example.com`. Контрагенты — реальные
  из `df_Uid_payment_hack.csv`: по два крупнейших получателя и плательщика, без переводов
  самому себе.
- Есть примеры пересмотренной оценки банка (`supersedes`) и устаревшего материала (`outdated`).
- Задержка ответов 300–800 мс. Добавьте `?mock=errors` к адресу страницы — все запросы вернут `500`.
- Состояние (прочитанные, скрытые, подтверждённые факты, настройки) хранится в `sessionStorage` вкладки: переживает перезагрузку, а новая вкладка начинает с исходных данных.

# Договор «бот ↔ бэкенд» «Радара»

Черновик до выдачи кейса. Бот на Go — отдельный сервис, он отвечает только за Telegram:
команды, отправку сообщений, лимиты и повторы. Пользователей, коды привязки, настройки и решение
«кому и что отправить» хранит и принимает бэкенд. В базу бот не ходит — только в этот API.

```
Сайт ──► бэкенд ◄── бот ──► Telegram
         (данные)   (доставка)
```

## Общие правила

- Префикс — `/internal/bot`. Наружу эти пути не открываются: только из внутренней сети
  или по секрету в заголовке `Authorization: Bearer <BOT_API_TOKEN>` (общий секрет в env обоих).
- JSON, даты ISO 8601, необязательные поля не передаются — как в `docs/api-contract.md`.
- Ошибки: код 4xx/5xx и тело `{ "code": "code_expired", "message": "Текст по-русски" }`.
  По `code` бот выбирает ответ пользователю, `message` — для логов.
- `chatId` — число (у Telegram до 52 бит, в JSON помещается без потерь).
- Названия полей инсайта — те же, что в основном контракте.

## Привязка аккаунта

### 1. Сайт просит ссылку (уже есть в основном контракте)

`POST /api/notifications/telegram/link` → `{ "url": "https://t.me/<BOT_USERNAME>?start=<code>" }`

Бэкенд создаёт код:

- 12 случайных символов `A-Z a-z 0-9` (`crypto`-генератор, не `Math.random`);
- живёт 15 минут, используется один раз;
- привязан к пользователю, который нажал «Подключить».

### 2. Бот подтверждает код

Пользователь нажал «Старт», бот получил `/start <code>`.

`POST /internal/bot/link/confirm`

```json
{ "code": "Ab3xK9pQr2Zt", "chatId": 123456789, "username": "demo_director" }
```

`username` не передаётся, если у пользователя его нет.

| Ответ                    | Когда               | Что пишет бот                                            |
| ------------------------ | ------------------- | -------------------------------------------------------- |
| `200 { "userId": "u1" }` | код верный          | «Готово. Срочные инсайты будут приходить сюда»           |
| `404 code_not_found`     | кода нет            | «Ссылка не подходит. Откройте её заново на сайте»        |
| `410 code_expired`       | прошло 15 минут     | «Ссылка устарела. Нажмите „Подключить Telegram“ ещё раз» |
| `409 code_used`          | код уже использован | «Эта ссылка уже использована»                            |

После `200` бэкенд ставит в настройках `telegram: { connected: true, username }` — сайт увидит это
при следующем `GET /api/notifications/settings`.

### 3. Бот отвязывает аккаунт

`POST /internal/bot/unlink` `{ "chatId": 123456789 }` → `204`

Когда: пользователь отправил `/stop` или заблокировал бота (Telegram вернул 403).
Бэкенд ставит `telegram: { connected: false }`. Отключение с сайта бэкенд делает сам, бот не участвует.

### 4. Статус для команды `/status`

`GET /internal/bot/status?chatId=123456789`

```json
{
  "connected": true,
  "companyName": "АО «Полевея Агро»",
  "urgentKinds": ["risk"],
  "digest": "daily",
  "digestTime": "09:00"
}
```

`404 not_linked`, если этот чат ни к кому не привязан.

## Доставка уведомлений

Бэкенд решает, **кому и что** отправить: учитывает `urgentKinds`, `digest`, `digestTime` и то,
подключён ли Telegram. Он складывает готовые доставки в очередь. Бот забирает их, отправляет и
отчитывается. Бот не нужен публичный адрес: он сам опрашивает бэкенд.

### 5. Забрать доставки

`GET /internal/bot/deliveries?limit=50` — бот вызывает раз в 10–15 секунд.

```json
{
  "items": [
    {
      "id": "d-1001",
      "chatId": 123456789,
      "kind": "urgent",
      "insight": {
        "id": "agro-flood",
        "kind": "risk",
        "urgency": "urgent",
        "title": "Паводок в Заречном районе: вода подошла к складской зоне",
        "whyItMatters": "Склад «Южный-2» в зоне паводка — под угрозой поставка упаковки на маслозавод",
        "checks": ["Запросить у склада статус отгрузки упаковки на сегодня и завтра"]
      }
    },
    {
      "id": "d-1002",
      "chatId": 123456789,
      "kind": "digest",
      "digest": {
        "since": "2026-10-11T00:00:00Z",
        "urgentRisks": 1,
        "risks": 5,
        "opportunities": 3
      }
    }
  ]
}
```

- `kind: "urgent"` приходит с `insight`, `kind: "digest"` — с `digest` (поля как у `GET /digest`).
- Пока доставку не подтвердили, бэкенд может отдать её снова — бот не дублирует по `id`.

### 6. Отчитаться о доставке

`POST /internal/bot/deliveries/{id}/ack`

```json
{ "status": "sent" }
```

| `status`  | Когда                             | Что делает бэкенд                                            |
| --------- | --------------------------------- | ------------------------------------------------------------ |
| `sent`    | Telegram принял сообщение         | больше не отдаёт эту доставку                                |
| `blocked` | Telegram вернул 403               | снимает привязку, как `unlink`                               |
| `failed`  | другая ошибка после всех повторов | можно передать `"error": "текст"`; повторит позже или бросит |

Повторы при 429 и 5xx от Telegram делает бот: ждёт `retry_after` или 1 → 2 → 4 с, до 3 раз.

## Что делает бот (для понимания, не часть API)

- Команды: `/start <code>`, `/stop`, `/status`, `/help`.
- Сообщение срочного инсайта — как превью на странице «Уведомления»: «Радар · Срочно · Риск»,
  заголовок, «почему касается», первый пункт «Что проверить», кнопка «Открыть в Радаре»
  (`<SITE_URL>/insights/<id>`). Без процентов вероятности; последствие — только с подписью «Гипотеза».
- Сводка: «С 11 октября: 1 срочный риск · 5 рисков · 3 возможности» и ссылка на ленту.
- Лимиты Telegram: не больше 1 сообщения в секунду в один чат и 30 в секунду всего.

## Пока бэкенда нет

Бот работает с заглушкой этого API в коде (тот же интерфейс, данные из `testdata/*.json`).
Для демо у бота есть `POST /dev/deliveries` — вбросить доставку и сразу получить её на телефон.

## Что обсудить с бэкендом

1. Устраивает ли модель «бэкенд решает, бот доставляет» — или бот сам считает, кому отправить.
2. Общий секрет `BOT_API_TOKEN` или внутренняя сеть в `docker-compose`.
3. `userId` и привязка к компании: один пользователь — одна компания или несколько.
4. Нужна ли история доставок на сайте (например, «последнее уведомление отправлено в 09:00»).

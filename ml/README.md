# ML-сервис «Радара»

Python-сервис, который превращает данные банка о компании, поток новостей и аналитику ЦМИ Альфа-Банка
в персональные выводы: что произошло, почему это касается именно этой компании, чем грозит или что даёт,
что проверить и как это оценивает банк. Плюс ответы на уточняющие вопросы и извлечение сведений о компании
из описания, ссылок и документов.

Сервис внутренний: его вызывает Java-бэкенд, наружу он не публикуется. Ответы уже в форме публичного API
из `api/` (InsightResponse, AskStream, ProfileFact), так что бэкенду остаётся хранить их, добавлять личные
статусы и проверять права.

```
Браузер ──► Java-бэкенд ──► ML-сервис ──► модели организаторов (только из Приложения 3)
                │               │
                │               ├─► RSS-источники новостей (по расписанию)
                │               ├─► SQLite: события, индекс аналитики, кэш LLM, трассы, готовые выводы
                │               └─► данные кейса (CSV) и PDF банка — только чтение, в volume
                └─► своя БД: пользователи, компании, факты, статусы, оценки
```

## Быстрый старт

Без ключа сервис работает целиком, но выводы собираются по правилам (`generatedBy: "rules"`).

```bash
cd ml
cp .env.example .env               # вписать RADAR_ML_LLM_API_KEY
# данные кейса: df_Uid_data_hack.csv, df_Fid_Uid_link_hack.csv, df_Uid_payment_hack.csv
mkdir -p data/raw data/materials && cp /путь/к/данным/*.csv data/raw/
cp /путь/к/аналитике/*.pdf data/materials/   # материалы ЦМИ из кейса
docker compose up --build          # http://127.0.0.1:8090/docs — Swagger
```

Локально без Docker:

```bash
cd ml
uv sync                            # Python 3.12, зависимости по uv.lock
uv run uvicorn radar_ml.api.app:app --port 8090
uv run pytest                      # тесты без сети и без лимита LLM
uv run python -m radar_ml.llm.check            # какие модели видит прокси, совпадают ли id в config/models.yaml
uv run python -m radar_ml.eval.run --golden eval/golden_demo.yaml   # эталон отбора
```

При первом старте с пустой базой загружается снимок новостей `snapshots/news.jsonl` (июль–октябрь 2026,
25 публикаций, 23 события), а PDF из `data/materials/` разбираются в базу аналитики. Для демо на снимке
задайте `RADAR_ML_REFERENCE_TIME=2026-10-23T18:00:00+03:00`, чтобы свежесть считалась от даты снимка.

Проверка: `curl -X POST localhost:8090/v1/companies/U_9250/feed -H 'Content-Type: application/json' -d '{"limit":5}'`.

## Как это работает

### 1. Бизнес-контекст компании — `radar_ml/profile`

Из датасета: отрасль по ОКВЭД → сектор (`config/sectors.yaml`), масштаб, регион, продукты банка, страны ВЭД,
группа компаний, контрагенты из платежей, связанные через физлиц компании. Положение в отрасли — место
по выручке и доля среди клиентов банка с тем же классом ОКВЭД. Это оценка по клиентской базе, а не доля рынка,
и в выводах так и подписано.

Главное — **факторы чувствительности**: через что внешние события бьют по компании. Ключевая ставка (кредиты,
лизинг), курс юаня (ВЭД с Китаем), цены на металл (отрасль или ключевой поставщик-металлург), госзаказ,
акцизы и так далее. У каждого фактора есть вес и происхождение: отрасль, продукт банка, страна ВЭД, контрагент,
группа или подтверждённое пользователем сведение. Веса складываются по noisy-OR. Пропуски в данных не
заполняются догадками и попадают в `dataQuality`. Пример: «данных ФТС нет — это не доказывает отсутствие ВЭД».

Сведения пользователей (подтверждённые факты) — самый точный источник. «Кредит с плавающей ставкой», «закупаем
технику в Китае за юани», «склад в Краснодарском крае» сразу добавляют факторы и связи. Для компаний не из
датасета профиль строится только по описанию и фактам.

### 2. Новости — `radar_ml/news`

- Источники в `config/sources.yaml`: RSS Банка России, Интерфакса, РБК, Коммерсанта, ТАСС, ПРАЙМ, Ведомостей.
  Сбой одного источника не останавливает остальные.
- Новость по ссылке или текстом (`POST /v1/news/ingest`). Так проверяется работа на ранее не показанных новостях.
- Извлечение в два слоя. Правила работают всегда: факторы, регионы, страны, валюты, числа, стадия события,
  направление (ставка сохранена, рубль укрепился, цены растут). Затем модель (Gemma 4, резерв — Qwen) по схеме.
  Её ответ проверяется: факторы только из справочника, числа и цитаты должны быть в тексте.
- Стадия: `occurred`, `discussed`, `decided`, `resolved`. «Минфин предложил» — обсуждение, а не решение.
  Слово «вступили в силу» в глубине текста не делает публикацию статистики решением.
- Дедупликация: перепечатка не создаёт новое событие, публикации об одном факте склеиваются в одно событие
  со списком источников. Существенное обновление (сменилась стадия, новые числа) повышает `version`.
- Шум (монеты ЦБ, спорт) и внутренняя регуляторика банков в ленту клиентов не попадает.

### 3. Аналитика банка — `radar_ml/bank`

PDF ЦМИ разбираются на фрагменты со страницами и индексируются BM25 со стеммингом. Эмбеддингов в списке
разрешённых моделей нет, поэтому поиск локальный и объяснимый.

**Позиция банка** — выжимка прогноза или оценки из материала со ссылкой на страницу. Позиции извлекаются при
загрузке материала: моделью (Qwen / DeepSeek) с обязательной цитатой, и все числа позиции обязаны быть
в материале. Без модели позиция берётся экстрактивно: предложения со словами «ожидаем/прогноз» и показателем
сохраняются как есть. Если по теме материала нет, позиция банка не формируется. Если банк пересмотрел оценку,
прежняя попадает в `supersedes`, и интерфейс показывает «было → стало». Материал старше
`RADAR_ML_BANK_MATERIAL_OUTDATED_DAYS` или помеченный экспертом считается устаревшим.

Таблицы и графики со страниц без текста описывает Qwen3-VL (если доступна).

### 4. Отбор и ранжирование — `radar_ml/matching`

Первый этап — без LLM, для всех событий сразу. Значимость складывается из именованных связей «событие —
признак компании»: фактор, отрасль, регион, страна ВЭД, контрагент, группа, сведение пользователя. Затем она
умножается на стадию, свежесть, доверие к источнику и важность события. Это балл приоритета, а не вероятность
убытка.

- **Главное** (`relevance: direct`) — событие задевает саму компанию, связь сильная, событие не устарело.
- **Под наблюдением** (`possible`) — связь только через контрагентов или группу, событие обсуждается,
  или оно в другом регионе.
- **Срочно** (`urgent`) — официальное решение или факт последних трёх суток с сильной прямой связью.
- Если событие про чужой рынок (зерно, топливо, алкоголь), совпадение только по общему фактору
  («пошлины», «налоги») ослабляется. Поэтому обнуление экспортной пошлины на зерно не попадёт в «Главное»
  дистрибьютору напитков.
- Серии: ожидания перед решением ЦБ убираются, когда решение принято; прошлое такое же решение уходит
  «под наблюдение» и остаётся предысторией для агента.
- Должность влияет только на порядок (`config/sectors.yaml → roles`): казначею выше ставки и валюта,
  бухгалтеру — налоги. Содержание вывода общее для компании, как требует API.

Предварительный вид (риск или возможность) задаётся правилами по направлению события и роли компании.
Например, укрепление рубля для импортёра — возможность, для экспортёра — риск. Агент может с этим
не согласиться, но должен обосновать.

### 5. Агент вывода — `radar_ml/agent`

Агент работает в несколько шагов, а не одним промптом:

1. **План.** Модель (Qwen) выбирает инструменты под событие. План проверяется: только инструменты из
   закрытого реестра, параметры по схеме. Обязательные шаги (событие, профиль, позиция банка) добавляются,
   если модель их пропустила.
2. **Инструменты** (только чтение, только эта компания): `event_details`, `company_profile`, `company_facts`,
   `counterparties`, `bank_search`, `bank_position`, `news_search`. Результаты складываются в общий контекст
   со ссылками: `S*` — источники, `C*` — признаки компании, `B*`/`BV` — аналитика банка, `E*` — связанные события.
3. **Черновик.** Модель для рассуждений (GLM-5.3-Flash, резерв — DeepSeek) пишет вывод по схеме и ссылается
   на контекст.
4. **Самопроверка** без модели (`agent/draft.py`):
   - цепочка влияния из 2–6 шагов заканчивается компанией;
   - 1–5 признаков компании, «почему важно» опирается минимум на два;
   - основания — только факты со ссылкой на источник;
   - все числа в выводе есть в источниках, данных компании или аналитике банка;
   - нет «вероятности 70%»;
   - позиция банка использована и влияет на последствия, если она есть, и не выдумана, если её нет;
   - последствие не пересказывает новость;
   - обсуждаемое событие не описано как принятое;
   - «что проверить» конкретно.

   Затем LLM-критик (Qwen) ищет противоречия и очевидные выводы.
5. **Адаптация.** Если не хватает данных, агент дозапрашивает: другой поиск по аналитике банка, контрагенты,
   сведения компании. Потом переписывает только проблемные места. Итераций не больше
   `RADAR_ML_AGENT_MAX_REVISIONS`.
6. **Отказоустойчивость.** Если модель недоступна, исчерпан лимит или черновик так и не прошёл проверку,
   собирается вывод по правилам (`agent/composer.py`) с пометкой `generatedBy: "rules"`. Он беднее, но не
   выдумывает. Невалидный ответ модели пользователю не показывается.

Каждый запуск пишет трассу (`GET /v1/traces/{id}`): план, вызовы инструментов с параметрами и результатом,
вызовы моделей с версией промпта, токенами и стоимостью, результаты проверок, использованные признаки и
источники. В сам вывод (`trace`) попадают только понятные пользователю шаги, без промптов.

Предложение банка (`offer`) модель не придумывает: оно выбирается правилами из каталога `config/offers.yaml`
и подписывается в интерфейсе как предложение банка.

### 6. Вопросы по выводу — `agent/ask.py`

`POST /v1/insights/ask` отдаёт тот же поток, что публичный `AskStream`: события `step`, затем `answer` или
`error`. Шаги настоящие: разбор вопроса → позиция банка и поиск по аналитике → данные компании → предыстория →
ответ (DeepSeek) → проверка ссылок и чисел. Можно спросить в другом разрезе: по контрагентам, группе,
горизонту, другой должности. Вопрос не по теме или о другой компании получает вежливый отказ без источников.
Без модели ответ собирается из позиции банка и самого вывода, и об этом прямо сказано в ответе.

### 7. Сведения о компании — `radar_ml/facts`

`POST /v1/facts/extract` (описание и ссылки) и `POST /v1/facts/extract-documents` (PDF, DOCX, TXT; тип —
по содержимому). У каждого факта есть категория, формулировка и дословное основание из источника. Выдуманное
основание отбрасывается. Отрицания сохраняются («склад не пострадал»). Со страницы поставщика на компанию
не переносятся его склады и ассортимент. Уже известные факты (в любом статусе) повторно не добавляются.
`unknownFields` подсказывает, чего не хватает для анализа.

## Модели и лимит

`config/models.yaml`: задача → модели по порядку (основная и резерв).

| Задача | Модели | Зачем |
|---|---|---|
| `news_extract`, `facts_extract`, `sector_classify` | Gemma 4 26B → Qwen3.6 | классификация, извлечение |
| `bank_positions` | Qwen3.6 → DeepSeek-V4.1-Flash | позиции банка из материалов |
| `bank_vision` | Qwen3-VL-30B | таблицы и графики в PDF |
| `insight_plan`, `insight_critic` | Qwen3.6 → Gemma / Kimi-K2.6 | план, критик |
| `insight_draft`, `insight_revise` | GLM-5.3-Flash → DeepSeek | рассуждение о влиянии |
| `ask_answer` | DeepSeek → GLM → Qwen | ответы на вопросы |

- Любая модель вне шести семейств из Приложения 3 блокируется при старте (`ALLOWED_FAMILIES`).
- Кэш: одинаковый вход — без повторного вызова. Готовые выводы кэшируются и пересчитываются только при новой
  версии события, изменении подтверждённых фактов или версии промптов.
- Учёт: токены и оценка стоимости по задачам и моделям (`GET /v1/usage`). При 80% дневного бюджета сервиса
  включается экономный режим: фоновые задачи (сбор ленты, разметка новостей) уходят на правила,
  интерактивные (вопросы, факты) продолжают работать. При 100% остаются только правила.
- Цены в `models.yaml` — оценка, её нужно сверить с фактическим списанием. Подтверждён только id
  `deepseek/deepseek-v4.1-flash` (из ноутбука команды), остальные — `python -m radar_ml.llm.check`.

## API для бэкенда

Swagger — `/docs`, OpenAPI — `/openapi.json`. Как публичные эндпойнты из `api/` ложатся на ML — в
[`docs/integration.md`](docs/integration.md).

| Метод | Что делает |
|---|---|
| `POST /v1/companies/{id}/profile` | профиль, факторы чувствительности, каталог признаков |
| `POST /v1/companies/{id}/candidates` | первый этап отбора: события с баллом и объяснением, без LLM |
| `POST /v1/companies/{id}/feed` | лента: кандидаты + готовые выводы (синхронно) |
| `POST /v1/companies/{id}/feed/jobs`, `GET /v1/jobs/{id}` | то же асинхронно: QUEUED → PROCESSING → DONE/FAILED |
| `POST /v1/insights/generate` | вывод по паре компания + событие |
| `POST /v1/insights/generate/stream` | то же с шагами агента потоком (SSE) |
| `POST /v1/insights/ask` | вопрос по выводу, поток как `AskStream` |
| `POST /v1/news/ingest` | новость по ссылке или текстом → событие |
| `POST /v1/news/collect`, `GET /v1/events` | сбор из источников, список событий |
| `POST /v1/facts/extract`, `POST /v1/facts/extract-documents` | сведения о компании |
| `GET/POST /v1/bank/materials`, `GET /v1/bank/search` | материалы банка, загрузка PDF, поиск |
| `GET /v1/traces/{id}` | полная трасса запуска |
| `GET /v1/usage`, `GET /v1/quality`, `GET /v1/dataset/quality` | лимит, метрики AI, качество данных |

Ошибки — Problem Details (`application/problem+json`), как в публичном API.

## Безопасность AI-компонента

- **Доступ.** Сервис внутренний (`X-Internal-Token`), права пользователя на компанию проверяет бэкенд.
  `companyId` контекста должен совпадать с запросом, вывод другой компании в вопрос не передать.
- **Инструменты.** Закрытый реестр, только чтение, параметры по схеме. `companyId` берётся из контекста,
  а не из ответа модели: модель не может запросить чужую компанию. Действие в выводе — только рекомендация.
  Каждый вызов пишется в `tool_calls` и в трассу.
- **Prompt injection.** Тексты новостей, документов и вопросов передаются модели как данные внутри контекста.
  Ответ принимается только в JSON по схеме и проверяется кодом: ссылки, числа, цитаты. Вопросы с попыткой
  переписать инструкции получают отказ.
- **Данные.** В модель уходят агрегаты: признаки, доли контрагентов, обезличенные ID. Сырых платежей там нет.
  Ключ модели — только в переменной окружения, в браузер не попадает. Логи без секретов.
- **Ссылки.** Только http(s), без внутренних и частных адресов, с лимитом размера, времени и перенаправлений.
- **Модели.** Только allowlist из кейса, дневной бюджет, экономный режим.

## Качество и мониторинг

Что меряем:

| Слой | Метрика | Откуда |
|---|---|---|
| Отбор | точность класса связи, пропущенные «Главное», ложные «Главное», точность вида (риск/возможность) | `eval/` |
| Контент | доля с позицией банка, с ≥2 признаками, с «что проверить», доля выводов модели против правил | `/v1/quality`, `api/metrics` |
| Агент | прошли самопроверку с первой попытки, доля переписываний и дозапросов, откаты на правила | `/v1/quality` |
| Стоимость и скорость | ₽ на вывод, p50 времени, расход лимита по задачам | `/v1/usage`, `/v1/quality` |
| Пользователи | «Полезно / не полезно», комментарии, скрытия, вопросы | бэкенд, `api/metrics` |
| Эксперты | случайная выборка выводов: факты, релевантность, глубина, корректность позиции банка | процесс ниже |

Процесс:

- **Каждый PR** — тесты и эталон на синтетических данных в CI (`.github/workflows/ml.yml`). Точность отбора
  ниже 0,9 ломает сборку.
- **Каждый день** — `/v1/quality` и `/v1/usage`. Сигналы: доля откатов на правила > 20%, первая самопроверка
  < 60%, стоимость вывода выросла вдвое.
- **Каждую неделю** — эксперт банка смотрит 20 случайных выводов и все с оценкой «не полезно». Плохие пары
  «компания — событие» уходят в `eval/golden_demo.yaml` с правильной разметкой.
- **При смене промпта, модели или правил** — прогон эталона с `--generate` и сравнение с прошлой версией
  (версия промпта пишется в трассу и в отчёт). При деградации откатываем версию промпта или конфига.

Честно о текущем эталоне: 25 пар на снимке новостей, разметка командой. На нём отбор даёт 0,96 точности
класса связи без пропущенных «Главное». Набор маленький, правила и разметку делали одни люди, поэтому это
проверка от регрессий, а не доказательство качества. Его нужно расширять разметкой экспертов.

## Масштабирование и сопровождение

- **Новый источник новостей** — запись в `config/sources.yaml`. Для не-RSS источника — класс-адаптер
  в `news/sources.py`.
- **Новая отрасль или тип клиента** — запись в `config/sectors.yaml`: префиксы ОКВЭД, факторы, роль во ВЭД.
  Новый внешний фактор — запись в `config/factors.yaml`: шаблоны, направления, запрос к аналитике.
- **Новый материал банка** — `POST /v1/bank/materials` или файл в `data/materials/`. Метаданные известных
  материалов — `config/materials.yaml`.
- **Новый инструмент агента** — функция и запись в `TOOLS` (`agent/tools.py`) со схемой параметров.
- **Модели** — `config/models.yaml`. Промпты лежат отдельно в `prompts/*.md` с версией в заголовке.
- **Эмбеддинги**, если организаторы их разрешат: `BM25Index.search` заменяется гибридным поиском
  без изменения инструментов.
- Состояние — один SQLite в volume. Для нескольких реплик его заменяет Postgres: работа с базой
  собрана в `store.py`.

## Конфигурация

Все переменные — с префиксом `RADAR_ML_`, полный список в `radar_ml/settings.py`, пример — `.env.example`.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `LLM_API_KEY` | — | ключ к прокси организаторов |
| `LLM_MODE` | `live` | `live` / `off` (только правила) / `stub` (тесты) |
| `LLM_DAILY_BUDGET_RUB` | 350 | дневной бюджет сервиса из общих 500 ₽ |
| `INTERNAL_TOKEN` | — | токен для бэкенда |
| `DATA_DIR`, `MATERIALS_DIR`, `STATE_DIR` | `data/...` | CSV кейса, PDF банка, состояние |
| `COLLECT_INTERVAL_MIN` | 0 | фоновый сбор новостей |
| `REFERENCE_TIME` | — | «сейчас» для демо на снимке |
| `FEED_MAX_INSIGHTS` | 12 | сколько выводов готовить в ленту |
